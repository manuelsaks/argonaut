Kargo promotion popup and upstream mode - 2026-11-10

Changes
- Promotion and Retry forms are centered, bordered, opaque popups above the
  dimmed originating list or describe/YAML view. They no longer replace it.
- Ctrl+P opens Promote; Ctrl+U on a target Stage opens Promote from upstream.
  Both modes are also available in the popup's Mode field: Shift+Tab from the
  choice field focuses Mode, Left/Right changes it, Tab advances through the
  choice and Cancel/Promote buttons. Enter activates; Esc closes the popup.
- Upstream mode matches the current Freight collection of the Stage's
  configured upstream Stages, by requested Warehouse origin. It intersects
  those IDs with Freight eligible for the target Stage. Historical Freight,
  another Warehouse and another project cannot become implicit choices.
- The popup shows source Stage(s), selected Freight/alias, target Stage,
  project and instance. Empty/ineligible choices cannot submit. Source Stage
  state is re-read before submitting; a changed upstream requires a new review.
- Normal Promote keeps all eligible Freight choices. Unfiltered eligible
  Freight lists remain cached across mode switches; only one project-level
  Stage list and, on a cold cache, one scoped Freight list are read for upstream.
- Every asynchronous response remains gated by view, epoch, sequence, exact
  target including promotion mode, and session identity. Writes are submitted
  once after explicit confirmation; no auth flow or refresh replays them.
- Sequential API calls receive separate configured per-call timeout budgets.
- Supports both REST and existing Connect clients without Kubernetes access.
