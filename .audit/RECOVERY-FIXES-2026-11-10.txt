Argo CD / Kargo recovery fixes - 2026-11-10

Changes
- Fetch ApplicationSets from /api/v1/applicationsets independently of app ownerReferences.
  Preserve namespace/context identity, including sets with zero generated Applications.
  Cache registries for five minutes; manual refresh bypasses the cache.
  The Argo CD ApplicationSet API does not support a fields projection.
- Authenticate enabled Argo CD contexts before opening them. The all view serializes
  CLI refresh / browser SSO across all enabled contexts rather than dropping busy logins.
  Handle missing credentials and loggedIn=false even when HTTP or CLI returns success.
  On later session failures, renew credentials from app, registry, inspection, events,
  resource action, delete/sync, refresh and tree-watch flows. Never replay writes.
  Genuine HTTP 403/RBAC denials remain permission errors; cancelled/failed SSO is throttled.
- Leave mouse capture disabled by default for native terminal selection/copy.
  Optional [clipboard] mouse_selection=true retains built-in drag selection.
  Ctrl+Y copies the complete document or focused diff pane. Report clipboard failures;
  Windows does not silently pretend an unsupported OSC 52 sequence copied successfully.
- Ctrl+T retries Failed / Errored / Aborted Kargo Promotions from the list or describe.
  A second Ctrl+T explicitly confirms instance/server/project/Stage/Freight.
  Re-read the original Promotion and reject a changed/non-retryable target before POST.
  Follow official Kargo UI semantics: create a new same-Freight, same-Stage Promotion
  using the current Stage template. Do not resume a failed step or replay writes.
