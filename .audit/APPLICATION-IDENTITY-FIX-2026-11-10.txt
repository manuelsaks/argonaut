Application names and ApplicationSet counts - 2026-11-10

Confirmed cause
Argo CD's Application list forwarder uses an exact field allowlist. It does
not treat items.metadata as a parent selector and does not expose
metadata.ownerReferences through projected lists. This was verified against
official v2.12.3, v3.0.0 and v3.2.0 sources. The old request therefore lost
Application names, metadata namespaces and owning ApplicationSets. Earlier
fixtures ignored field projection and returned full metadata regardless.

Changes
- Initial/explicit Application loads request one complete list. This supplies
  names, metadata namespaces and ownerReferences together, before watch events.
- Routine polling requests the supported exact metadata leaf fields, keeps
  known ownership by Application namespace/name, and checks creationTimestamp
  before reusing it. A new/recreated Application triggers one full batch read.
- Complete metadata is refreshed every five minutes and on Ctrl+R. Contexts,
  servers and sessions have separate caches; changing server or credentials
  invalidates the cached ownership snapshot.
- Keep this behavior in both a single context and the all-context overview.
  No per-Application metadata request fan-out was added.
- Reject list rows without metadata.name instead of rendering blank names and
  admitting nameless objects into the operation index.
- Fixtures now emulate Argo CD's actual projected metadata behavior.
